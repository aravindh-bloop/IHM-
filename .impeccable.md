# Design Context - IHM (Restaurant Management System)

## Users
Three distinct user types with equal importance:
- **Stall Workers/Chefs**: Managing orders and inventory in fast-paced kitchen environments
- **Administrators**: System-wide oversight and configuration
- **Vendors/Suppliers**: External partners managing product relationships

All users work in **high-stress, time-critical contexts** where every second matters. The interface must support rapid decision-making and task completion without cognitive overhead.

## Brand Personality
**Modern • Decisive • Efficient**

The system should feel:
- Contemporary and confident (not corporate or bland)
- Action-oriented and purposeful
- Trustworthy and command full attention
- Fast without sacrificing clarity

## Aesthetic Direction
**Modern, Bold, Sophisticated**

Visual language should reflect:
- Sharp, intentional typography with clear hierarchy
- Decisive use of color (strategic accents, not timid)
- Asymmetric layouts that break monotony
- Responsive to user actions with confidence
- Professional yet approachable
- Both light and dark modes optimized for different contexts

### Anti-References
- Generic SaaS templates (overused card layouts, hero metrics)
- Overly playful or cute design (misses the professional context)
- Dark mode with neon glows (cliché)
- Massive amounts of card nesting or visual noise
- Rounded corners with drop shadows as lazy accents

## Design Principles

1. **Speed First**: Every interaction should feel instantaneous. Use optimistic UI updates. Eliminate unnecessary steps.

2. **Information Hierarchy**: Show what matters most immediately. Use progressive disclosure for secondary information.

3. **Confident Color**: Employ bold, purposeful color choices. Dominant colors with sharp accents outperform timid palettes.

4. **Asymmetric Layouts**: Break the monotony of grids. Use varied spacing and unexpected compositions for visual interest.

5. **Type as Expression**: Typography should be distinctive and intentional. Avoid system defaults and overused fonts.

6. **Dark Mode Intelligence**: Dark mode should be optimized for evening/low-light work contexts, not just a visual toggle of light mode.

## Tech Stack
- React 19 with Vite
- Tailwind CSS + custom CSS
- Material-UI (optional, can be replaced for distinctive design)
- Recharts for visualizations
- Lucide React for icons

## Implementation Notes
- Leverage Tailwind for rapid iteration while building custom components for distinctive details
- Use CSS variables for cohesive, maintainable theming
- Design at component level with container queries for responsive behavior
- Prioritize performance: minimal animations, smooth transitions
- Empty states and loading states should teach the interface, not just placeholder content
